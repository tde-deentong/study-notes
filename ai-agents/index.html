Overview

The core loop

An agent is a model inside a loop.

Context

Model proposes action

Tool runs

Observation

then repeat

Most of the engineering is in the harness: prompts, tools, memory, limits, and error handling

The loop ends on a stop signal, a step limit, or a budget

Each part of the loop is a lever for evaluation and training

The model reads its context, emits an action (usually a tool call), the environment returns an observation, and the loop continues until the task is done or a limit is hit.

Block 1 · Capabilities

Tools are the agent's hands

Describe

Name, description, and typed schema. The description changes how the model uses the tool.

Dispatch

Parse the call, validate arguments, execute, and return the result.

Return errors as observations, not crashes, so the model can recover

Cap retries per tool and per task

Description quality often matters more than people expect. The result of a tool call goes back to the model as an observation.

Block 1 · Capabilities

The window is finite and expensive

Compaction

Summarize old turns when the window fills; keep goals, constraints, and open issues

Progressive disclosure

Show skill names and short descriptions first; load full text only when used

Retrieval

Pull in only the memory relevant to this step

Assignment 1 implements compaction and progressive disclosure.

Every token has a cost in latency and attention.

Block 1 · Capabilities

Skills and memory

Skills

Reusable procedures the agent loads on demand. Written once, used across tasks.

Memory

Facts and past outcomes that persist across sessions. Needs rules for what to write, when to read, and when to delete.

Stale memory is a silent failure: the agent acts confidently on outdated facts.

Block 1 · Capabilities

Interleave or plan first?

Interleave

Think

Act

Observe

Plan first

Plan once

Execute

Replan if surprised

Plan-first is easier to inspect, but brittle when the environment disagrees

Step limits and budget tracking stop runaway loops

ReAct interleaves reasoning and acting step by step. Plan-then-execute separates a planning call from execution.

Block 3 · Reinforcement learning

Fundamentals

MDP view

State, action, reward, transition, discount. An agent episode is a trajectory of these.

Policy gradient

Increase the probability of actions that appear in high-return trajectories

Advantage

Reward minus a baseline, which reduces variance

KL regularization

Keep the trained policy close to a reference model to prevent drift

KL regularization also guards against degenerate outputs, not only drift.

Block 3 · Reinforcement learning

Rewards for agents

Verifiable rewards

Tests pass, exact-match answer, game outcome. The cleanest signal.

LLM-as-judge rewards

Cheaper to obtain, but exploitable.

Reward hacking: the policy scores well without solving the task, such as special-casing tests or exploiting the grader.

Block 3 · Reinforcement learning

Practical issues

Credit assignment

Over 50 actions, which one mattered?

Sparse rewards

Most trajectories fail, so the learning signal is thin

Sampling cost

Every rollout runs tools in an environment

Block 4 · Safety and frameworks

Why sandbox agents

Agents run code and tools with real side effects.

Deleting files

Calling networks

Spending money

Sending messages

Run untrusted code in isolated environments (containers or microVMs)

Limit network and filesystem access

Least privilege: give each tool only the permissions the task needs

Block 4 · Safety and frameworks

Threats

Prompt injection

Instructions hidden in tool outputs, web pages, or files hijack the agent

Overreach

The agent takes a broader action than the user intended

Test or reward gaming

Covered in Block 3, with safety consequences here

Block 4 · Safety and frameworks

Mitigations

Human checkpoints

Before irreversible actions

Trust separation

Keep trusted instructions separate from untrusted observations in the prompt

Trajectory logs

So failures can be audited

Block 5 · Human interaction and search

Search at test time

Best-of-N

Sample several attempts, pick the best

Verifier-guided selection

Score attempts with a checker or model

Tree search

Explore alternative action sequences, with a value signal at each node

Trade-off: more search gives better results at higher compute and latency cost.
